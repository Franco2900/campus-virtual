ACTORES DEL SISTEMA

Usuario:
Persona que utiliza el sistema. Puede registrarse y autenticarse.

Estudiante:
Usuario que posee el rol de Estudiante. Puede inscribirse en cursos, entregar tareas y consultar sus calificaciones.

Profesor:
Usuario que posee el rol de Profesor. Puede gestionar tareas, gestionar inscripciones y corregir tareas de los cursos correspondientes.

Administrador:
Usuario que posee el rol de Administrador. Puede gestionar cursos, gestionar usuarios e inscripciones y filtrar usuarios.

Regla general de roles:
Cada usuario puede tener exactamente un rol a la vez. Los roles son mutuamente excluyentes. Por ejemplo, un Profesor no puede ser simultáneamente Estudiante y un Estudiante no puede ser simultáneamente Administrador.
Los usuarios nuevos reciben inicialmente el rol Estudiante.
El rol de Profesor es asignado por un Administrador.

















CU-01 — REGISTRARSE

Actor principal:
Usuario no registrado.

Objetivo:
Permitir que un usuario cree una cuenta en el sistema.

Precondiciones:
- El usuario no posee una cuenta registrada.
- El correo electrónico no se encuentra asociado a otra cuenta.

Flujo principal:
1. El usuario selecciona la opción Registrarse.
2. El sistema solicita los datos necesarios para crear la cuenta.
3. El usuario ingresa nombre, apellido, correo electrónico y contraseña.
4. El sistema verifica que el correo electrónico no se encuentre registrado.
5. El sistema valida los datos ingresados.
6. El sistema crea la cuenta.
7. El sistema asigna inicialmente el rol Estudiante.
8. El sistema confirma el registro.

Postcondiciones:
- La cuenta del usuario queda registrada.
- El usuario posee el rol Estudiante.
- El correo electrónico queda asociado de forma única a la cuenta.

Reglas:
- El correo electrónico funciona como identificador único de la cuenta.
- Un usuario solo puede poseer un rol a la vez.



















CU-02 — AUTENTICARSE

Actor principal:
Usuario.

Objetivo:
Permitir que un usuario inicie y cierre sesión y pueda recuperar el acceso a su cuenta.

Precondiciones:
- El usuario posee una cuenta registrada.

Flujo principal — Inicio de sesión:
1. El usuario ingresa su correo electrónico y contraseña.
2. El sistema verifica las credenciales.
3. Si las credenciales son correctas, el sistema inicia la sesión.
4. El sistema identifica el rol del usuario.
5. El sistema permite acceder a las funcionalidades correspondientes a dicho rol.

Flujo alternativo A1 — Credenciales incorrectas:
1. El sistema informa que el correo electrónico o la contraseña son incorrectos.
2. El usuario puede volver a ingresar sus credenciales.

Flujo alternativo A2 — Recuperación de contraseña:
1. El usuario selecciona la opción de recuperación de contraseña.
2. El sistema solicita el correo electrónico asociado a la cuenta.
3. El usuario ingresa su correo electrónico.
4. El sistema verifica que la cuenta exista.
5. El sistema envía un enlace de recuperación al correo electrónico registrado.
6. El usuario accede al enlace y establece una nueva contraseña.

Flujo alternativo A3 — Cerrar sesión:
1. El usuario selecciona la opción Cerrar sesión.
2. El sistema finaliza la sesión activa.

Reglas:
- Cada usuario posee un único rol.
- El acceso a las funcionalidades depende del rol del usuario.












CU-03 — GESTIONAR CURSOS

Actor principal:
Administrador.

Objetivo:
Permitir al Administrador crear, consultar, modificar y desactivar cursos.

Precondiciones:
- El Administrador inició sesión.
- El usuario posee el rol Administrador.

Flujo principal:
1. El Administrador accede a la gestión de cursos.
2. El sistema muestra los cursos registrados.
3. El Administrador selecciona una operación: crear, consultar, modificar o desactivar.
4. Para crear un curso, el Administrador ingresa los datos correspondientes.
5. El sistema valida los datos.
6. El sistema registra el nuevo curso.
7. Para consultar un curso, el sistema muestra la información correspondiente.
8. Para modificar un curso, el Administrador selecciona el curso e ingresa los nuevos datos.
9. El sistema valida y guarda las modificaciones.
10. Para desactivar un curso, el Administrador selecciona el curso.
11. El sistema cambia el estado del curso a inactivo.

Reglas:
- Un curso puede tener múltiples estudiantes.
- Un curso puede tener múltiples profesores.
- Un curso puede encontrarse activo o inactivo.
- Los cursos inactivos no deben tratarse como cursos activos.


















CU-04 — GESTIONAR USUARIOS

Actor principal:
Administrador.

Objetivo:
Permitir al Administrador gestionar las cuentas de usuarios y sus roles.

Precondiciones:
- El Administrador inició sesión.
- El usuario posee el rol Administrador.

Flujo principal:
1. El Administrador accede a la gestión de usuarios.
2. El sistema muestra los usuarios registrados.
3. El Administrador selecciona un usuario.
4. El sistema muestra la información correspondiente.
5. El Administrador puede gestionar los datos y el rol del usuario.
6. El sistema valida la operación.
7. El sistema guarda los cambios.

Flujo alternativo A1 — Asignar rol de Profesor:
1. El Administrador selecciona un usuario.
2. Selecciona la opción para asignar el rol Profesor.
3. El sistema solicita confirmación.
4. El Administrador confirma.
5. El sistema asigna el rol Profesor.
6. El usuario deja de poseer el rol anterior, manteniendo exactamente un rol.

Flujo alternativo A2 — Cambiar rol de Profesor a Estudiante:
1. El Administrador selecciona un usuario que posee el rol Profesor.
2. Selecciona la opción para cambiar su rol a Estudiante.
3. El sistema solicita confirmación.
4. El Administrador confirma.
5. El sistema asigna el rol Estudiante.

Reglas:
- Cada usuario debe poseer exactamente un rol.
- Los roles son mutuamente excluyentes.
- La asignación del rol Profesor corresponde al Administrador.

CU-05 — GESTIONAR INSCRIPCIONES

Administrador, Profesor.

Objetivo:
Permitir gestionar las inscripciones de estudiantes en los cursos.

- El usuario que realiza la operación inició sesión.
- El usuario posee el rol Administrador o Profesor.
- El curso existe y se encuentra disponible para la operación.

Flujo principal:
1. El Administrador o Profesor accede a la gestión de inscripciones.
2. El sistema muestra los cursos correspondientes.
3. El usuario selecciona un curso.
4. El sistema muestra los estudiantes y sus inscripciones.
5. El usuario selecciona la operación correspondiente.
6. El usuario registra, modifica o elimina una inscripción.
7. El sistema valida la operación.
8. El sistema guarda la inscripción actualizada.
9. El sistema muestra el resultado de la operación.

Reglas:
- Las inscripciones se realizan sobre cursos existentes.
- Un profesor solo puede inscribir estudiantes en los cursos en los que trabaja.
- Un estudiante puede estar inscripto en los cursos que correspondan.
- La gestión de inscripciones no genera notificaciones automáticas por correo electrónico.

CU-07 — ENTREGAR TAREA

Actor principal:
Estudiante.

Objetivo:
Permitir que el Estudiante entregue, modifique o elimine una tarea antes de la fecha límite.

Precondiciones:
- El Estudiante inició sesión.
- El usuario posee el rol Estudiante.
- El Estudiante está inscripto en el curso correspondiente.
- La tarea se encuentra disponible.
- No se superó la fecha límite para realizar la entrega.

Flujo principal:
1. El Estudiante accede al curso.
2. El sistema muestra las tareas disponibles.
3. El Estudiante selecciona una tarea.
4. El Estudiante adjunta o ingresa su trabajo.
5. El sistema verifica que la entrega se encuentre dentro del plazo.
6. El sistema registra la entrega.
7. El sistema confirma la operación.

Flujo alternativo A1 — Modificar entrega:
1. El Estudiante selecciona una entrega existente.
2. Modifica el trabajo presentado.
3. El sistema verifica que no se haya superado la fecha límite.
4. El sistema verifica que la tarea no se haya corregido todavía.
5. El sistema actualiza la entrega.

Flujo alternativo A2 — Eliminar entrega:
1. El Estudiante selecciona una entrega existente.
2. Solicita eliminarla.
3. El sistema solicita confirmación.
4. El Estudiante confirma.
5. El sistema elimina la entrega.

Reglas:
- El Estudiante solo puede entregar tareas de cursos en los que se encuentre inscripto.
- La entrega debe realizarse antes de la fecha límite.







CU-08 — CORREGIR TAREA

Actor principal:
Profesor.

Objetivo:
Permitir que el Profesor corrija las entregas, asigne una calificación y proporcione retroalimentación.

Precondiciones:
- El Profesor inició sesión.
- El usuario posee el rol Profesor.
- El Profesor está asociado al curso correspondiente.
- Existe una entrega realizada por un estudiante.

Flujo principal:
1. El Profesor accede al curso.
2. El sistema muestra las tareas.
3. El Profesor selecciona una tarea.
4. El sistema muestra las entregas recibidas.
5. El Profesor selecciona una entrega.
6. El sistema muestra el trabajo presentado.
7. El Profesor analiza la entrega.
8. El Profesor ingresa una calificación entre 1 y 10.
9. El Profesor ingresa la retroalimentación correspondiente.
10. De manera opcional, el Profesor puede adjuntar un archivo corregido.
11. El sistema valida la información ingresada.
12. El sistema guarda la corrección.
13. El sistema determina automáticamente si la tarea está aprobada o desaprobada según la calificación correspondiente.

Flujo alternativo A1 — Modificación de corrección:
1. El Profesor selecciona una entrega que ya fue corregida.
2. Modifica la calificación o la retroalimentación.
3. El sistema valida los datos.
4. El sistema guarda la nueva corrección.

Reglas:
- La calificación debe encontrarse entre 1 y 10.
- Cada corrección puede incluir retroalimentación.
- El archivo corregido es opcional.
- La corrección no genera una notificación automática por correo electrónico.







CU-09 — CONSULTAR CALIFICACIONES

Actores principales:
Profesor, Estudiante.

Objetivo:
Permitir consultar las calificaciones obtenidas en las tareas.

Precondiciones:
- El usuario inició sesión.
- El usuario posee el rol Profesor o Estudiante.

Flujo principal:
1. El usuario accede a la sección de calificaciones.
2. El sistema identifica el rol del usuario.
3. Si el usuario es Estudiante, el sistema muestra sus propias calificaciones.
4. Si el usuario es Profesor, el sistema muestra las calificaciones de los estudiantes de sus cursos.
5. El sistema muestra las calificaciones correspondientes.
6. El sistema calcula el promedio según las reglas establecidas.

Reglas:
- El promedio se calcula mediante un promedio simple.
- Las tareas no corregidas no se incluyen en el cálculo del promedio.
- Las tareas no entregadas fuera del plazo correspondiente se contabilizan con calificación 1.
- El Estudiante solo puede consultar sus propias calificaciones.
- El Profesor puede consultar las calificaciones de los estudiantes de sus cursos.

CU-11 — UTILIZAR CHATBOT DE ASISTENCIA

Actor principal:
Usuario autenticado (Estudiante, Profesor o Administrador).

Objetivo:
Permitir que los usuarios realicen consultas sobre el funcionamiento de la plataforma y obtengan información real del sistema mediante un chatbot basado en inteligencia artificial, respetando los permisos correspondientes a su rol. Permitir también consultar conversaciones anteriores y eliminar completamente el historial propio del chatbot.

Precondiciones:
    • El usuario inició sesión en la plataforma.
    • El usuario posee uno de los roles definidos en el sistema: Estudiante, Profesor o Administrador.
    • El chatbot se encuentra disponible para recibir consultas.
    • Las fuentes de información necesarias se encuentran disponibles.

Flujo principal:
    1. El usuario accede al chatbot desde la plataforma.
    2. El sistema habilita la interfaz de conversación.
    3. El usuario ingresa una consulta.
    4. El sistema identifica al usuario autenticado y su rol.
    5. El chatbot analiza la consulta para determinar qué información necesita para responder.
    6. Si la consulta se relaciona con el funcionamiento de la plataforma, el chatbot utiliza las fuentes de conocimiento administradas y aprobadas como referencia principal. Puede recurrir a sus conocimientos generales cuando resulte útil, sin inventar funcionalidades específicas de la aplicación.
    7. Si la consulta requiere información real del sistema, el chatbot obtiene los datos necesarios de la base de datos mediante operaciones autorizadas para el rol del usuario.
    8. El chatbot utiliza el contexto de la conversación actual y, cuando corresponda, el historial de conversaciones anteriores del mismo usuario.
    9. El chatbot genera una respuesta en español, clara y amable, cuya extensión se adapta a la consulta.
    10. El sistema muestra la respuesta al usuario.
    11. El usuario puede continuar la conversación, consultar conversaciones anteriores o acceder a la opción de eliminar su historial.

Flujos alternativos:
A1 — Usuario no autenticado
    1. Una persona intenta acceder al chatbot sin haber iniciado sesión.
    2. El sistema impide el acceso al chatbot.
    3. El sistema solicita que la persona inicie sesión para utilizarlo.

A2 — Consulta sobre información no disponible
    1. El usuario realiza una consulta que requiere información que no se encuentra disponible o que no puede determinarse con suficiente certeza.
    2. El chatbot informa que no dispone de información suficiente para responder con certeza.
    3. Cuando resulte útil, proporciona información general relacionada, sin presentarla como un dato confirmado de la plataforma.
    4. Cuando corresponda, recomienda consultar con un profesor o administrador.

A3 — Consulta sobre información no autorizada
    1. El usuario solicita información que excede los permisos correspondientes a su rol.
    2. El sistema impide el acceso a dicha información.
    3. El chatbot informa que no puede proporcionar los datos solicitados.

A4 — Solicitud de modificación o ejecución de operaciones
    1. El usuario solicita crear, modificar o eliminar información de la plataforma mediante el chatbot.
    2. El chatbot informa que no puede ejecutar esa operación y, cuando corresponda, orienta al usuario hacia la funcionalidad correspondiente de la plataforma.

A5 — Solicitud de corrección o calificación de tareas
    1. El usuario solicita que el chatbot corrija una entrega o asigne una calificación.
    2. El chatbot informa que esas operaciones corresponden al profesor y que no forman parte de sus funciones.

A6 — Consulta ajena a la función del chatbot
    1. El usuario realiza una consulta que no está relacionada con el funcionamiento de la plataforma educativa.
    2. El chatbot explica brevemente que su función es ayudar a utilizar la plataforma y consultar información del sistema.
    3. El chatbot redirige al usuario hacia ese propósito sin responder la consulta ajena a su función.

A7 — Error al consultar información o generar una respuesta
    1. Se produce un error que impide consultar la base de datos o generar una respuesta.
    2. El chatbot informa que no pudo completar la consulta.
    3. Cuando corresponda, indica que el usuario puede intentarlo nuevamente.

A8 — Consulta relacionada con una conversación anterior
    1. El usuario realiza una consulta que hace referencia a una conversación previa.
    2. El chatbot recupera el historial disponible correspondiente a ese usuario.
    3. El chatbot utiliza el contexto recuperado para interpretar y responder la consulta.
    4. Si no dispone del contexto necesario, informa la limitación y solicita la información que falte cuando sea necesario.

A9 — Eliminar el historial del chat
    1. El usuario accede a la sección de historial o configuración del chatbot.
    2. El sistema ofrece la opción de eliminar completamente el historial de conversaciones del usuario.
    3. El usuario selecciona la opción de eliminación.
    4. El sistema informa que la operación eliminará el historial guardado y que no podrá recuperarse desde la aplicación.
    5. El sistema solicita confirmación antes de continuar.
    6. El usuario confirma la operación.
    7. El sistema elimina las conversaciones y los mensajes almacenados correspondientes al usuario, junto con las memorias persistentes o los resúmenes derivados de esas conversaciones que se utilicen para personalizar respuestas futuras.
    8. El sistema confirma que la eliminación se completó.
    9. El chatbot deja de utilizar el historial eliminado como contexto para futuras consultas.

A9.1 — Cancelación de la eliminación
    1. El usuario decide cancelar la operación antes de confirmarla.
    2. El sistema conserva el historial existente.
    3. El usuario puede continuar utilizando el chatbot.

Postcondiciones:
    • El usuario recibe una respuesta o una explicación de por qué no puede responderse su consulta.
    • La información proporcionada respeta los permisos correspondientes al rol del usuario.
    • Las consultas de información se realizan sin modificar los datos funcionales de la plataforma.
    • El historial se conserva asociado a la cuenta del usuario mientras no sea eliminado.
    • Cuando el usuario elimina su historial, las conversaciones y las memorias derivadas contempladas en la operación dejan de estar disponibles para su recuperación y utilización por el chatbot.

Reglas de negocio:
    1. El chatbot solamente puede ser utilizado por usuarios autenticados.
    2. El chatbot está disponible para los roles Estudiante, Profesor y Administrador.
    3. El chatbot debe respetar los permisos de acceso existentes en la plataforma para cada rol.
    4. El chatbot no debe revelar información a usuarios que no estén autorizados a consultarla.
    5. Los datos concretos sobre cursos, inscripciones, tareas, entregas y calificaciones deben obtenerse de las fuentes autorizadas del sistema. El chatbot no debe inventar ni presentar como confirmados datos que no pudo verificar.
    6. Las fuentes de conocimiento administradas por el Administrador constituyen la referencia principal para explicar el funcionamiento de la plataforma y responder preguntas específicas contempladas en ellas.
    7. Los conocimientos generales del modelo pueden utilizarse como complemento, pero no deben utilizarse para inventar funcionalidades o reglas de la aplicación.
    8. El chatbot no puede crear, modificar ni eliminar información funcional de la plataforma, ni ejecutar operaciones en nombre del usuario. La eliminación del historial propio constituye la excepción expresamente autorizada por este caso de uso.
    9. El chatbot no puede corregir entregas ni asignar calificaciones.
    10. Cuando no disponga de información suficiente, el chatbot debe reconocer sus limitaciones, evitar especular y recomendar consultar con un profesor o administrador cuando corresponda.
    11. El chatbot debe limitar sus respuestas a las funciones definidas para la plataforma educativa.
    12. El chatbot debe responder en español, utilizando un tono claro y amable y adaptando la extensión de sus respuestas a cada consulta.
    13. El historial de conversaciones debe mantenerse asociado al usuario correspondiente y no puede ser accesible por otros usuarios sin autorización.
    14. Cuando el usuario elimine su historial, el sistema debe eliminar los datos de conversaciones y las memorias derivadas incluidas en el alcance de la operación. Esta acción no debe eliminar cursos, tareas, entregas, inscripciones, calificaciones ni otros datos funcionales almacenados por la plataforma.
    15. La recuperación y utilización de conversaciones anteriores deben limitarse al historial que siga disponible y pertenezca al usuario autenticado.
    16. Las validaciones de identidad, permisos y eliminación de datos deben realizarse en el backend y no depender únicamente de las instrucciones proporcionadas al modelo de inteligencia artificial.
    17. La eliminación del historial debe gestionarse de forma que los datos eliminados no puedan volver a incorporarse al contexto del chatbot desde copias de trabajo, cachés o memorias persistentes controladas por la aplicación.














































CU-12 — GESTIONAR FUENTES DE CONOCIMIENTO DEL CHATBOT

Actor principal:
Administrador.

Objetivo:
Permitir que el Administrador gestione los archivos que funcionan como fuentes de conocimiento autorizadas del chatbot, mediante la carga y eliminación de documentos que establezcan información sobre el funcionamiento de la plataforma y respuestas aprobadas para determinadas consultas.

Precondiciones:
    • El Administrador inició sesión en la plataforma.
    • El usuario posee el rol Administrador.
    • El servicio de gestión de fuentes de conocimiento se encuentra disponible.

Flujo principal:
    1. El Administrador accede a la sección de gestión de fuentes de conocimiento del chatbot.
    2. El sistema verifica que el usuario posea el rol Administrador.
    3. El sistema muestra los archivos registrados como fuentes de conocimiento y permite consultar la información necesaria para identificarlos.
    4. El Administrador selecciona la operación que desea realizar: cargar un archivo o eliminar uno existente.
    5. El sistema procesa la operación seleccionada.

Flujos alternativos:
A1 — Cargar un archivo
    1. El Administrador selecciona la opción para cargar un archivo.
    2. El sistema solicita seleccionar el archivo e ingresar, cuando corresponda, información descriptiva, su finalidad y los roles a los que está dirigido.
    3. El Administrador selecciona el archivo e ingresa la información solicitada.
    4. El sistema valida que el archivo cumpla los requisitos establecidos para su carga.
    5. El sistema almacena el archivo y procesa su contenido para incorporarlo a las fuentes de conocimiento del chatbot.
    6. El sistema registra la información necesaria para identificar la fuente y determinar a qué consultas o roles se aplica.
    7. Una vez completado correctamente el procesamiento, el sistema habilita la fuente para su utilización por el chatbot.
    8. El sistema informa al Administrador que la operación finalizó correctamente.

A2 — Eliminar un archivo
    1. El Administrador selecciona un archivo registrado.
    2. El sistema muestra la información que permite identificar la fuente seleccionada.
    3. El Administrador solicita eliminarla.
    4. El sistema solicita confirmación.
    5. El Administrador confirma la operación.
    6. El sistema elimina el archivo de las fuentes activas de conocimiento y retira su contenido de los mecanismos de búsqueda o recuperación utilizados por el chatbot.
    7. El sistema informa que la fuente fue eliminada correctamente.

A3 — Usuario sin permisos suficientes
    1. Un usuario sin el rol Administrador intenta acceder a la sección o ejecutar una operación de gestión de archivos.
    2. El sistema rechaza la solicitud.
    3. El sistema informa que la operación requiere permisos de Administrador.

A4 — Archivo no válido
    1. El Administrador intenta cargar un archivo que no cumple los requisitos establecidos, está dañado o no puede procesarse.
    2. El sistema rechaza la carga o el procesamiento.
    3. El sistema informa el motivo cuando pueda determinarlo.
    4. El archivo no se incorpora a las fuentes activas del chatbot.

A5 — Error durante la carga o el procesamiento
    1. Se produce un error al almacenar el archivo o procesar su contenido.
    2. El sistema informa que no pudo completar la operación.
    3. El sistema evita presentar como disponible una fuente cuyo procesamiento no haya finalizado correctamente.

A6 — Cancelación de la eliminación
    1. El Administrador solicita eliminar una fuente.
    2. El sistema solicita confirmación.
    3. El Administrador cancela la operación.
    4. El sistema conserva el archivo y mantiene su estado anterior.

A7 — Consulta basada en una fuente eliminada
    1. Un usuario realiza una consulta cuyo contenido estaba cubierto por una fuente de conocimiento eliminada.
    2. El chatbot consulta las fuentes de conocimiento que permanecen disponibles.
    3. El chatbot responde utilizando la información vigente que pueda verificar.
    4. Si no dispone de información suficiente, reconoce la limitación y no presenta el contenido eliminado como una fuente vigente.

Postcondiciones:
    • Las fuentes cargadas y procesadas correctamente quedan disponibles para las consultas autorizadas del chatbot.
    • Las fuentes eliminadas dejan de estar disponibles para las nuevas consultas del chatbot.
    • Las fuentes y sus operaciones de gestión quedan bajo el control exclusivo de usuarios autenticados con el rol Administrador.

Reglas de negocio:
    1. Únicamente un usuario autenticado con el rol Administrador puede cargar o eliminar fuentes de conocimiento del chatbot.
    2. Las verificaciones de permisos deben realizarse en el backend para impedir operaciones no autorizadas.
    3. Las fuentes de conocimiento pueden incluir:
        ◦ Guías de uso de la plataforma.
        ◦ Instrucciones para Estudiantes, Profesores y Administradores.
        ◦ Documentación de las funcionalidades y reglas de negocio del sistema.
        ◦ Preguntas frecuentes y sus respuestas aprobadas.
        ◦ Preguntas o situaciones determinadas para las que se haya definido una respuesta que el chatbot deba proporcionar.
    4. Los archivos deben cumplir los requisitos de formato, tamaño y procesamiento establecidos por el sistema.
    5. Una fuente solamente puede utilizarse como conocimiento disponible después de que su carga y procesamiento hayan finalizado correctamente.
    6. Cada fuente debe poder identificarse y asociarse, cuando corresponda, con los roles a los que está dirigida y el propósito de su contenido.
    7. El chatbot debe utilizar únicamente la información pertinente y autorizada para el rol del usuario. Una guía dirigida a un rol no debe revelar información restringida a los demás.
    8. Cuando una consulta coincida con una pregunta o situación que tenga una respuesta expresamente aprobada, el chatbot debe priorizar esa respuesta y conservar su significado, sin sustituirla por una respuesta contradictoria generada por el modelo.
    9. Cuando las fuentes de conocimiento establezcan una regla específica de la plataforma, el chatbot debe priorizar esa información frente a sus conocimientos generales. Si encuentra información contradictoria o insuficiente, debe reconocer la limitación en lugar de inventar una regla.
    10. El contenido de las fuentes de conocimiento no otorga permisos adicionales al usuario ni permite omitir los controles de acceso definidos en la plataforma.
    11. Al eliminar una fuente, el sistema debe retirarla del almacenamiento y de los mecanismos de recuperación activos utilizados por el chatbot, de manera que no siga siendo utilizada como fuente vigente en futuras respuestas.
    12. La eliminación de una fuente de conocimiento no implica eliminar el historial de conversaciones en el que ya se hubiera mencionado su contenido.
    13. La carga, el procesamiento, la activación y la eliminación de fuentes deben reflejar correctamente el estado de cada archivo para evitar que el chatbot utilice contenido incompleto o retirado.
    14. La gestión de estas fuentes no permite al Administrador modificar directamente, mediante el chatbot, los datos funcionales de los usuarios, cursos, tareas, entregas, inscripciones o calificaciones.
    15. Los formatos de archivo admitidos, sus límites de tamaño y las condiciones de conservación deben definirse durante el diseño técnico de la funcionalidad.
